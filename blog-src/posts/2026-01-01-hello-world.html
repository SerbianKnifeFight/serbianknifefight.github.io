This used to say "newsletter" at the top of the page, which was a lie in the way small lies about your own website tend to be. A newsletter implies a cadence, an audience expecting something, a format you promise to repeat. What I actually wanted was closer to a notebook that other people happen to be able to read: essays when I have an actual argument to make, project logs when something ships or breaks, and diary entries when nothing in particular is happening but I want a record of it anyway.

So this is the rebuilt version of that notebook. Same bones as the rest of the site — same orange topbar, same cream page, same tree-shaped sidebar that's been the site's whole personality since I stopped trying to make it look like anything other than what it is — but stretched out into something built for reading, not just browsing.

what changed, mechanically

Every post now lives at its own address instead of being a chunk of a JavaScript object switched in and out of view. That was fine for a portfolio page where nothing needed a permalink, but it's a bad way to run a blog: no stable links, no RSS, nothing search engines or feed readers can hold onto. This version generates real files — one per post — plus an rss.xml that updates itself every time something new goes up.

The sidebar tree isn't decoration. It's the same file-explorer conceit as the rest of the site, doing the same job here: showing you the shape of the archive before you commit to reading any of it.

what it's for

Three kinds of posts, loosely:

  • essays — actual arguments about whatever's stuck in my head that week
  • project logs — devlog-shaped updates on the things listed elsewhere on this site
  • diary entries — less structured, more "here's what's going on"

They all live in the same stream instead of three separate blogs, because that's closer to how a person's attention actually moves — the tag list in the sidebar is there for anyone who wants to filter.

how it's built

No CMS, no database, no build step you need a server for. Each post is a plain HTML file with a small comment block on top for the title, date, type, and tags. A short Python script reads all of them and generates the index, the individual post pages, and the RSS feed. Run the script, commit the output, done — the same static-file philosophy as the rest of the site, just with a few more moving parts.

python3 build.py

That's the whole deploy process. No framework lock-in, nothing to keep updated, nothing that breaks when some JavaScript package gets abandoned in three years.
